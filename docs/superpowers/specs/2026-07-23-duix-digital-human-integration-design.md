# DUIX 实时数字人接入设计

日期：2026-07-23

## 1. 背景与目标

项目已经具备受数据库配置驱动的 AI 服务商、实时面试追问、训练记录、报告生成、CosyVoice 语音和灵眸数字人生命周期管理。

本阶段新增硅基 DUIX 作为实时数字人服务商，并将其作为 `DIGITAL_HUMAN_REALTIME` 能力的首选实现。现有灵眸适配器继续保留为可配置的备用服务商，但运行时不会在 DUIX 失败后自动切换到灵眸，以避免产生不可预期的付费调用。

首轮真实联调使用 DUIX 会话中配置的声音。现有 CosyVoice 配置和代码继续保留，外部 CosyVoice 音频驱动 DUIX 属于后续阶段。

## 2. 已确认决策

- 保留灵眸，新增 `DUIX` 服务商。
- DUIX 配置完整后成为实时数字人的当前选中模型。
- 现有面试后端继续负责题纲、提问、实时追问、回答记录和报告。
- DUIX 只负责浏览器中的数字人渲染、播报、打断和会话释放。
- 首轮关闭 DUIX 自带 ASR 和自动大模型回答，候选人回答继续走项目现有识别链路。
- DUIX 不可用时降级到本地数字人，文字面试不中断。
- 浏览器端只接收短期签名，不接收 `appSecret`。
- 真实凭据未就绪时先完成自动化测试、构建和降级路径验证，凭据就绪后再执行真实会话联调。

## 3. 方案比较

### 3.1 采用方案：后端控制面试，DUIX 负责呈现

现有后端生成面试官文本，前端通过 DUIX H5 SDK 的直驱能力播报文本。面试事实来源仍然是项目自己的训练会话和轮次数据。

优点：

- 不改变现有追问、题纲约束和报告证据链。
- DUIX、灵眸和本地数字人可以继续通过统一能力选择机制切换。
- 后续替换语音模型或增加外部音频驱动时，不需要迁移面试业务逻辑。

代价：

- 需要维护 DUIX 签名接口和浏览器 SDK 生命周期。
- 首轮使用 DUIX 内置声音，与现有 CosyVoice 音色可能存在差异。

### 3.2 未采用方案：DUIX 全链路对话

DUIX 同时负责 ASR、LLM、TTS 和数字人。接入路径较短，但追问逻辑和面试记录会分散到两个系统，不利于报告证据一致性。

### 3.3 未采用方案：DUIX 回调现有面试接口

DUIX 接收语音后回调本项目生成回答。该方案需要公网 HTTPS、回调鉴权、幂等和超时补偿，首轮复杂度过高。

## 4. 配置模型

### 4.1 服务商

在服务商类型中新增 `DUIX`。

服务商公开设置：

- `platform`：默认使用官方 H5 SDK 要求的平台域名。

服务商加密凭据：

- `appId`
- `appSecret`

`appSecret` 使用项目现有 AES-256-GCM 配置加密机制保存，不进入模型设置、前端响应、日志或错误消息。

### 4.2 模型

实时数字人模型保存：

- `conversationId`
- `client: "web"`
- `interactionMode: "direct-drive"`
- `speechMode: "duix-managed"`

推荐参考模型使用 `isDefault=true`。只有凭据和 `conversationId` 配置完整且管理员明确选择后，模型才使用 `isSelected=true`。运行时继续遵守“推荐默认不等于当前选择”的现有语义。

管理员完成 DUIX 配置时，系统将 DUIX 设为 `DIGITAL_HUMAN_REALTIME` 的当前选中模型，并取消灵眸模型的当前选中状态。配置不完整时不自动选中 DUIX，避免面试房间进入不可用状态。

## 5. 服务端设计

### 5.1 凭据解析

新增独立的 DUIX 凭据解析器，负责：

- 验证服务商类型为 `DUIX`。
- 解密并验证 `appId`、`appSecret`。
- 验证模型能力、`conversationId` 和适配器契约。
- 只抛出固定错误码，不在错误中包含原始凭据。

### 5.2 签名

签名在服务端按 DUIX 官方规则生成，并使用短有效期。签名实现使用可注入的当前时间，便于测试过期时间和载荷。

浏览器获得的会话连接对象仅包含：

- 短期 `sign`
- `conversationId`
- `platform`
- 项目内部数字人会话 ID
- 过期时间

### 5.3 会话接口

复用现有数字人会话入口和数据库生命周期，增加 DUIX 模式：

- 创建前校验训练会话仍处于进行中。
- 读取当前选中的实时数字人模型。
- 当前模型为 DUIX 时创建内部会话记录并返回短期连接参数。
- DUIX 配置不完整或签名失败时创建本地降级会话。
- 心跳继续更新内部会话活动时间。
- 删除、训练结束或过期回收时将内部会话标记为停止。

DUIX H5 会话主要由浏览器 SDK 的 `stop()` 释放。服务端删除接口负责项目内部所有权和状态收口，不能假设浏览器的卸载请求一定送达。

### 5.4 诊断

后台诊断分两层：

- 静态诊断：检查服务商、加密凭据、`conversationId` 和适配器配置。
- 主动诊断：仅在管理员点击后生成短期签名并调用官方的轻量鉴权检查，不自动创建付费数字人会话。

诊断结果使用固定、安全的错误码；响应和日志不得包含 `appSecret` 或完整签名。

## 6. 浏览器端设计

新增 `duixAvatarClient`，向面试组件暴露稳定接口：

- `start(connection, root)`
- `speak(text, interrupt)`
- `interrupt()`
- `exit()`

SDK 实例存放在 React `ref` 中，不放入响应式 state。

启动流程：

1. 用户进入面试并产生明确点击行为。
2. 前端请求项目数字人会话。
3. 收到 DUIX 连接参数后动态加载 H5 SDK。
4. 在固定容器中初始化 SDK。
5. 等待初始化成功和数字人可见事件。
6. 以关闭 ASR、关闭自动回答的直驱模式启动。
7. 将后端生成的问题传给 `speak()`。

播报新问题时使用打断语义，避免上一段语音和新追问重叠。页面退出、任务切换、会话结束和 React 清理时必须保证 `exit()` 幂等。

## 7. 降级与错误处理

以下情况切换本地数字人：

- 未选择或未完整配置 DUIX。
- 签名生成失败。
- SDK 下载或初始化失败。
- 初始化超时、首帧超时或 SDK 报错。
- 播报失败。

降级动作：

- 立即停止正在初始化或运行的 DUIX 客户端。
- 通知服务端收口内部会话状态。
- 将界面模式切换为 `LOCAL_AVATAR`。
- 显示可理解的降级提示。
- 保留题目文字和回答功能。

运行时不会自动切换到灵眸。管理员可以在后台主动把当前模型切回灵眸。

## 8. UI 设计

后台：

- 服务商表单在类型为 DUIX 时显示 `appId`、`appSecret` 和平台字段。
- 实时数字人模型在服务商为 DUIX 时显示 `conversationId` 和只读适配器模式。
- 诊断面板区分“未配置”“静态配置有效”“主动鉴权成功”和“主动鉴权失败”。

面试房间：

- DUIX 成功时显示“DUIX 实时数字人”。
- 降级时显示“本地数字人降级”及简短原因。
- 不再把所有真实数字人统一显示成“灵眸”。
- 题目文字始终可见。

## 9. 安全与隐私

- `appSecret` 只存在于加密数据库配置和服务端解密后的短生命周期内存中。
- 短期签名不写入日志、数据库和客户端持久化存储。
- 签名接口受现有认证、训练会话归属校验和限流保护。
- 错误响应只返回固定错误码和安全提示。
- `.env` 不保存 DUIX 业务凭据，Git 不提交任何真实凭据。
- 麦克风继续由现有语音识别链路管理；首轮 DUIX 不额外采集麦克风。

## 10. 测试与验收

### 10.1 自动化测试

- 服务商常量、后台字段和模型设置解析测试。
- 凭据加密、解析和缺失字段测试。
- 签名载荷、有效期、错误脱敏测试。
- 会话创建、心跳、停止、过期和并发所有权测试。
- DUIX 客户端初始化、播报、打断、退出和超时测试。
- 面试组件成功模式与本地降级测试。
- 诊断静态检查和主动检查测试。
- 推荐模型与当前选中模型语义测试。
- Linux 和 Docker 部署契约测试。

### 10.2 构建验证

- 全量 Vitest。
- TypeScript 类型检查。
- Next.js 生产构建。
- Docker Compose 同源构建、健康检查和基本页面检查。
- 验证完成后停止应用容器和 Docker Desktop。

### 10.3 真实联调

用户取得 `appId`、`appSecret` 和 `conversationId` 后：

- 在后台录入加密凭据。
- 主动执行 DUIX 鉴权诊断。
- 创建一个短时训练任务。
- 验证初始化、播报、打断、追问、退出和计费会话释放。
- 检查失败时是否正确降级且不影响训练记录。

## 11. 实施阶段

### 阶段 0：隔离未完成灵眸修改

当前工作区四个未提交的灵眸端渲染修改不属于本设计。实施前使用只包含这四个已跟踪文件的可恢复 Git stash 保存，不包含根目录未跟踪文件。DUIX 从当前已经推送的稳定灵眸基线开发。

### 阶段 1：配置、签名与诊断

新增 DUIX 服务商、模型配置、加密凭据解析、签名和诊断。先写失败测试，再实现。完成后测试、提交并推送。

### 阶段 2：数字人会话与浏览器 SDK

新增 DUIX 会话模式、客户端适配器和房间状态。完成后测试、构建、提交并推送。

### 阶段 3：Docker 同步与真实凭据联调

同步部署文档和 Docker 契约，完成同源镜像构建。真实凭据就绪后执行真实会话联调。测试结束后停止容器和 Docker Desktop。

## 12. 非目标

本阶段不包含：

- 使用 DUIX 自带 LLM 接管面试追问。
- 使用 DUIX ASR 替换现有识别链路。
- CosyVoice 外部音频流驱动 DUIX。
- DUIX 与灵眸之间的运行时自动付费切换。
- 创建或购买 DUIX 平台资源。
