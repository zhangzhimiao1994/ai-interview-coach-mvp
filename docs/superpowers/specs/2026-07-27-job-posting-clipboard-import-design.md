# 招聘页面剪贴板导入设计

## 背景与目标

现有招聘信息导入支持服务端读取公开 HTTP(S) 页面，并在页面要求登录、验证码或安全验证时提示用户手工粘贴 JD。下一阶段增加“从剪贴板解析”，让用户在浏览器中自行完成招聘网站登录，复制当前页面可见的岗位正文，再由开发面试数字人解析并回填任务表单。

系统不接管招聘网站账号，不保存密码、Cookie、会话令牌或验证码，也不尝试绕过网站的访问控制。Selenium 或其他自动化登录不属于本阶段范围。

## 方案选择

评估过三种方式：

1. 表单内剪贴板导入：无需安装组件，用户登录和复制动作清晰可控，适合当前产品阶段。
2. 浏览器扩展或书签脚本：可直接读取当前页，但需要额外安装、权限审核和版本维护。
3. Selenium/RPA 托管登录：自动化程度高，但凭据、风控、验证码、站点条款和长期维护成本最高。

采用方案 1。现有“公开链接自动导入”和“直接编辑 JD 文本框”继续保留，三者互为补充。

## 用户流程

1. 用户在招聘网站中自行登录并打开目标职位。
2. 用户复制页面中可见的职位正文；可以复制纯文本，也可以复制 HTML 源内容。
3. 用户回到训练任务表单，点击“从剪贴板解析”。
4. 浏览器读取剪贴板并把内容和可选的来源链接提交到现有招聘导入接口。
5. 服务端清洗内容、提取岗位标题、公司、JD 正文和要求，并返回结构化结果。
6. 表单回填 JD；只有目标公司或岗位为空时才自动回填，避免覆盖用户已经填写的内容。
7. 用户检查、补充后创建训练任务，JD 才随任务保存并进入面试上下文。

## 接口与解析

`POST /api/job-postings/import` 支持两类互斥输入：

- `{ "url": "https://..." }`：保持现有公开页面抓取行为。
- `{ "content": "...", "sourceUrl": "https://..." }`：解析用户主动复制的内容；`sourceUrl` 可省略。

请求必须至少提供 `url` 或 `content`。剪贴板内容去除首尾空白后不得过短，并限制最大长度，避免误操作和过大请求。若提供 `sourceUrl`，仍必须是公开 HTTP(S) URL，防止把内网地址写入任务来源。

内容包含 HTML 标签时复用现有 HTML 清洗器；纯文本则规范换行和空白，使用第一条合理的非空行作为候选岗位标题，并从职责、要求、经验、资格等中英文关键词行提取要求。登录提示、验证码和安全验证页面继续返回 `PASTE_REQUIRED`，不把无效页面当作 JD。

## 安全与隐私

- 前端只在用户点击按钮时申请剪贴板读取权限。
- 服务端不接收招聘网站账号、密码、Cookie、Authorization 头或浏览器会话。
- 剪贴板内容在导入接口中只用于解析并返回；用户提交训练任务前不写入数据库。
- 接口不执行剪贴板中的脚本，HTML 只按文本清洗。
- 自动抓取继续限制为公开 HTTP(S) 地址，并阻止本机、链路本地和私有网段。

## 错误处理

- 剪贴板为空或内容太短：提示用户复制完整 JD 后重试。
- 浏览器拒绝剪贴板权限：提示用户允许权限，或直接粘贴到 JD 文本框。
- 内容是登录/验证码页面：提示重新复制实际职位正文。
- 解析结果没有有效正文：保留已有表单内容并显示可恢复提示。
- 来源链接不安全：返回 400，不发起网络请求。

## 测试与验收

按照测试驱动方式实现：

- 领域测试覆盖纯文本解析、HTML 剪贴板解析、要求提取和来源链接保留。
- 路由测试通过真实 `Request` 内容调用接口，不发起外部网络请求，验证剪贴板输入和错误输入。
- UI 合约测试确认按钮、剪贴板读取、接口请求字段和失败提示存在。
- 完整运行项目测试套件和生产构建。
- 本阶段不启动 Docker；验证后提交并推送当前 GitHub 分支。

验收标准是：用户可在任意国内外招聘网站自行登录后复制可见 JD，通过一次点击完成解析回填；系统不保存登录凭据，也不依赖 Selenium。
