# 公司专业化数字人面试系统设计

## 目标

将当前通用 AI 面试训练工具升级为面向付费服务的专业化系统。系统需要根据目标公司、岗位、候选人材料和面试轮次生成拟真的专业面试大纲，由数字人面试官进行实时面试，并把候选人的回答、语音和视频行为信号纳入复盘评分。

第一版重点不是追求最昂贵的视频数字人，而是建立可持续扩展的专业化底座：公司模板库、岗位能力库、面试剧本库、AI 草稿审核、数字人面试配置、多模型能力路由和细分后台运营台。

## 核心原则

- 专业性来自公司和岗位知识库，而不是通用面试提示词。
- AI 生成内容必须先进入草稿状态，由人工审核后才能用于真实训练。
- 模型供应商不绑定单一厂家，后台按能力类型配置主模型、备用模型和 fallback。
- 神态评分只描述行为信号及其面试影响，不做医学、心理或人格诊断。
- 数字人第一版采用轻量可落地方案，后续再接入更高拟真度的视频数字人服务。
- 每个结论都要能追溯到候选人回答、上传材料、公司模板或人工审核记录。

## 范围

本设计覆盖下一阶段产品架构和后台信息架构：

1. 公司情报库、岗位能力库、面试剧本库。
2. AI 生成草稿和人工审核发布流程。
3. 公司/岗位/简历驱动的专业面试大纲。
4. 轻量数字人面试官和候选人行为信号评分。
5. 模型与服务商的能力路由。
6. 更细颗粒度的后台导航和运营工作区。

本设计不直接要求第一版实现联网自动抓取公司资料，也不直接实现高成本全视频数字人生成。公网资料解析和第三方数字人平台接入作为后续扩展点。

## 资料进入系统的流程

第一版采用“AI 生成草稿 + 人工审核发布”。

```text
上传 JD / 简历 / 公司资料 / 面经
→ AI 抽取公司与岗位画像
→ AI 生成公司模板、岗位模板、题库和面试剧本草稿
→ 后台人工审核、修改、补充来源
→ 发布为可用模板
→ 创建候选人训练任务
→ 生成专业面试大纲和数字人面试剧本
→ 实时面试与复盘报告
```

资料来源需要标记等级：

```text
VERIFIED_MANUAL     顾问确认过
UPLOADED_MATERIAL   来自上传 JD、简历、公司资料或面经
EXTERNAL_SOURCE     来自外部链接或网页
AI_INFERRED         AI 推测，只能作为草稿参考
```

AI 推测内容不能直接作为“事实”展示给候选人，也不能直接进入已发布模板。发布前必须由后台用户确认或改写。

## 核心模板资产

### 公司模板

公司模板描述公司层面的面试环境和业务背景：

- 公司基础信息、行业、业务模式。
- 主要产品线、业务线和竞品。
- 组织文化、价值观、面试风格。
- 常见面试轮次和面试官角色。
- 近期关注点，例如增长压力、新业务、组织调整、产品方向。
- 风险与禁区，例如敏感话题、不可确认的信息、禁止 AI 推断的内容。
- 资料来源、审核人、审核状态和更新时间。

### 岗位模板

岗位模板作为可复用能力库，不强绑定单一公司：

- 岗位族：产品、运营、前端、后端、算法、销售、咨询等。
- 岗位等级：实习、初级、中级、高级、管理岗。
- 核心职责和能力模型。
- 专业知识点和业务场景。
- 技术、业务、产品或 case 深挖点。
- 常见专业题和追问题。
- 优秀回答要素、评分标准和红线表现。

### 面试剧本

面试剧本定义“怎么面”，而不只是“问什么”：

- 轮次模板：HR、一面、二面、终面、压力面、英文面。
- 面试官类型：HR、业务负责人、技术专家、直属经理、压力型面试官等。
- 问题顺序和阶段切换规则。
- 追问策略、打断策略和等待时长。
- 时间控制和阶段开关。
- 数字人语气、神态和表情状态。
- 候选人行为观察点。

## 专业面试大纲生成

下一版大纲必须由三类输入共同生成：

```text
公司模板 + 岗位模板 + 候选人简历/材料
```

每道题需要包含以下字段：

```text
问题类型：业务深挖 / 技术深挖 / Case / 压力追问 / 价值观 / 英文
公司背景：为什么这家公司可能会问这个问题
岗位能力：考察哪项专业能力
标准答案方向：优秀回答应覆盖的要点，不生成背诵稿
追问策略：回答浅、虚、错、逃避时分别如何追问
评分规则：专业性、业务理解、方法论、证据质量、表达稳定性
风险信号：背稿、泛泛而谈、不了解公司业务、缺少数据
```

同一岗位在不同公司应生成不同问题风格。例如：

- 字节类：指标、增长、A/B 实验、快速迭代、压力追问。
- 腾讯类：用户价值、产品体验、协作、长期判断。
- 华为类：执行力、业务结果、稳定性、抗压、组织适配。
- 外企类：英文表达、跨文化沟通、ownership、behavioral questions。
- 咨询类：case 拆解、商业逻辑、结构化推理、数字敏感度。

## 数字人面试官

第一版采用轻量可落地数字人，而不是直接上昂贵全视频生成：

```text
AI 面试官文本追问
→ TTS 语音合成
→ 数字人头像/半身像
→ 口型同步或状态化嘴型动画
→ 表情状态切换
→ 前端实时播放
```

数字人应具备明确面试状态：

```text
开场寒暄
正式提问
等待候选人回答
轻微点头/注视
根据回答追问
必要时打断或施压
阶段切换
总结反馈
```

表情和语气状态至少包括：

```text
中性
鼓励
等待
追问
质疑
严肃
总结
```

后续可接入 HeyGen、D-ID、腾讯智影、MiniMax，或自研 Live2D/Three.js 方案。第一版先保留 `DIGITAL_HUMAN_RENDER` 能力类型，避免把渲染实现写死。

## 候选人神态与行为评分

候选人摄像头和麦克风信号纳入评分，但报告只描述可观察行为信号：

```text
眼神：是否长期偏离屏幕
低头：是否频繁看稿
表情：是否僵硬、紧张、缺少回应
停顿：长停顿次数和出现位置
语速：过快、过慢、忽快忽慢
音量：是否过低或波动大
稳定性：回答中断、重复、口头禅
互动感：追问后是否能迅速恢复表达
```

报告输出格式：

```text
观察到的行为信号
可能造成的面试影响
对应训练建议
```

禁止输出人格判断、医学判断或心理诊断。例如不能写“候选人性格不自信”，应写“在三次追问中出现长停顿和视线下移，可能影响面试官对表达稳定性的判断”。

## 模型与服务商能力路由

系统按能力类型配置模型，不把模型写死在代码里：

```text
COMPANY_PROFILE_EXTRACTION     公司资料抽取
JD_RESUME_EXTRACTION           JD/简历解析
COMPANY_TEMPLATE_DRAFT         公司模板草稿生成
ROLE_TEMPLATE_DRAFT            岗位模板草稿生成
QUESTION_BANK_DRAFT            专业题库草稿生成
INTERVIEW_PLAYBOOK             面试剧本生成
LIVE_DIGITAL_INTERVIEWER       实时数字人面试官
VISION_BEHAVIOR_ANALYSIS       候选人视频行为分析
ASR                            语音识别
TTS                            语音合成
DIGITAL_HUMAN_RENDER           数字人渲染
REPORT_ANALYSIS                报告生成
REPORT_REVIEW                  报告复核
```

后台每个能力可以配置：

```text
主服务商
主模型
备用服务商
备用模型
超时时间
最大 token
温度
成本备注
是否启用 fallback
是否需要人工审核
质量评分
```

默认候选模型基于官方文档和账号可用列表定期更新，不作为代码依赖，也不把具体型号写死在业务逻辑里。后台初始化时只预置供应商和能力类型，具体 model id 由管理员按服务商控制台实际可用项填写和测试：

- OpenAI：适合作为复杂大纲、专业报告、实时语音、转写和多模态任务的候选供应商。可在后台维护 GPT 文本/推理模型、Realtime、TTS、转写和视觉相关模型。
- Anthropic Claude：适合作为长上下文分析、专业复核、报告生成和风险检查的候选供应商。可在后台维护 Opus、Sonnet、Haiku 等不同成本和能力档位。
- Google Gemini：适合作为多模态理解、视频行为解释、实时语音和视觉任务的候选供应商。可在后台维护 Gemini 文本、多模态、Live、TTS 和视觉相关模型。
- 阿里云百炼/通义千问：适合作为中文资料处理、国内部署、ASR、TTS、多模态和成本控制的候选供应商。可在后台维护 Qwen 文本/多模态、实时语音、ASR 和语音合成模型。

每个具体模型上线前必须通过后台“连通性测试 + 小样本质量测试 + 成本备注 + fallback 测试”，测试通过后才能绑定到生产能力类型。

推荐第一版默认路由：

```text
资料抽取：低成本文本模型
公司/岗位模板草稿：强推理文本模型
专业剧本生成：强推理文本模型
实时数字人面试官：Realtime/Live 模型
ASR：实时转写或专业 ASR
TTS：可控语气的语音合成模型
视频行为分析：多模态视觉模型
报告生成：强分析模型
报告复核：不同服务商的第二模型
```

模型调用日志必须记录服务商、模型、能力类型、耗时、失败原因、fallbackProvider、人工是否采纳、成本估算和关联训练任务。

## 后台信息架构

后台需要比当前更细，按服务运营流程拆成以下一级模块：

### 1. 总览工作台

- 今日训练场次。
- 待审核模板数量。
- 待复盘报告数量。
- 模型调用失败数量。
- 高风险候选人。
- 即将面试候选人。
- 服务顾问待处理事项。

### 2. 候选人管理

- 基础信息、联系方式、目标公司、目标岗位。
- 简历、作品集、上传材料。
- 面试时间线和服务阶段。
- 历史训练记录、弱项标签、顾问备注。
- 服务状态和后续可扩展的付款状态。

### 3. 训练任务

连接候选人与专业模板：

```text
候选人 + 目标公司 + 目标岗位 + 面试轮次 + 数字人 + 模型配置
= 一次专业训练任务
```

训练任务可配置：

- 目标公司模板。
- 目标岗位模板。
- 面试轮次。
- 面试官类型。
- 数字人形象和语气。
- 训练强度。
- 是否启用神态评分。
- 是否启用报告复核。

### 4. 公司情报

- 公司基础信息、业务线、产品线。
- 行业、竞品、商业模式。
- 组织文化和面试风格。
- 常见轮次、近期关注点、风险与禁区。
- 来源证据、审核状态、发布状态。

### 5. 岗位能力

- 岗位族、岗位等级、核心能力模型。
- 专业知识点、业务场景、深挖点。
- 常见题、优秀回答要素、评分标准、红线表现。

### 6. 面试剧本

- 轮次模板。
- 面试官类型。
- 提问顺序。
- 追问策略。
- 打断策略。
- 阶段切换规则。
- 时间控制。
- 数字人语气与表情状态。
- 候选人行为观察点。

### 7. AI 审核

集中处理所有 AI 生成草稿：

- 公司模板草稿。
- 岗位模板草稿。
- 专业题库草稿。
- 面试剧本草稿。
- 报告建议草稿。
- 来源不足提醒。
- 人工修改记录。
- 审核通过、驳回、归档。

状态流转：

```text
DRAFT_AI
→ NEEDS_REVIEW
→ APPROVED / REJECTED
→ ARCHIVED
```

### 8. 数字人

- 数字人角色。
- 头像、半身像、声音。
- 语速、语气、音色。
- 表情状态。
- 追问强度。
- 打断频率。
- 等待时长。
- 严肃、温和、压力型等 persona。

### 9. 报告复盘

- 候选人最终报告。
- 专业能力得分。
- 表达与行为信号评分。
- 逐题证据。
- 公司匹配风险。
- 下一次训练计划。
- 顾问服务建议。
- 候选人可见版本和内部版本区分。
- 可导出报告。

### 10. 模型配置

- 服务商管理：OpenAI、Claude、Gemini、Qwen、MiniMax 等。
- API Key 管理。
- 模型列表。
- 能力类型绑定。
- 默认模型、备用模型。
- 成本备注、超时设置、失败 fallback。
- 调用日志、质量评分、采纳率。

### 11. 系统设置

- 账号与权限。
- 服务套餐。
- 安全设置。
- 审计日志。
- 数据保留策略。

## 权限与角色

第一版可以先用管理员账号，但设计上应预留角色：

```text
OWNER           系统拥有者
ADMIN           后台管理员
CONSULTANT      服务顾问
REVIEWER        模板审核员
CANDIDATE       候选人
```

候选人只能看到自己的训练入口和候选人版报告。顾问可以查看候选人、训练任务和报告。审核员可以审核模板草稿。管理员可以配置模型和服务商。

## 报告输出分层

同一份分析数据拆成两个视图：

### 候选人视图

- 面试结论。
- 主要风险。
- 逐题反馈。
- 行为信号提示。
- 优先改进项。
- 七天训练计划。

### 顾问视图

- 公司匹配风险。
- 证据台账。
- 胜任力矩阵。
- 行为信号明细。
- 服务跟进建议。
- 是否建议继续训练、模拟哪一轮、补哪类材料。

报告复核模型需要检查：

- 是否过于笼统。
- 是否脱离公司和岗位模板。
- 是否编造公司事实。
- 是否把行为信号写成心理诊断。
- 是否缺少逐题证据。

## 错误处理与风控

- AI 草稿缺少来源时，标记为来源不足，不能发布。
- 模型调用失败时记录失败原因和 fallbackProvider。
- 实时数字人服务不可用时，降级为文字面试官 + TTS 或纯文字。
- 视频行为分析不可用时，报告明确显示“未启用行为信号评分”。
- 公司资料不足时，大纲只能生成通用专业题，不能伪装成公司专属题。
- 外部来源和联网资料必须标记时间、URL 和采集状态。

## 测试要求

- 公司模板、岗位模板、剧本状态流转测试。
- AI 草稿审核通过后才能用于训练任务的测试。
- 面试大纲必须包含公司背景、岗位能力、追问策略和评分规则的测试。
- 模型能力路由、默认模型、备用模型、fallback 日志测试。
- 数字人状态机测试：开场、提问、等待、追问、阶段切换、总结。
- 行为信号评分测试：输出行为描述和训练建议，不输出心理诊断。
- 候选人视图与顾问视图的数据隔离测试。

## 分阶段实施建议

### Phase 1：专业模板底座

- 公司情报、岗位能力、面试剧本数据模型。
- AI 草稿审核中心。
- 训练任务绑定公司、岗位和剧本。
- 专业大纲结构升级。

### Phase 2：数字人面试体验

- 轻量数字人面试官。
- TTS 语音合成。
- 面试官状态机。
- 实时追问与阶段切换。

### Phase 3：行为信号评分

- 摄像头和麦克风采集。
- 语速、停顿、音量等音频行为信号。
- 基础视频行为信号。
- 报告中加入行为信号解释。

### Phase 4：模型路由增强

- 多服务商能力绑定。
- 调用质量评分。
- 报告复核模型。
- 模型成本和失败率看板。

### Phase 5：资料自动化增强

- URL 解析。
- 外部资料采集。
- 公司模板库批量维护。
- 专业题库沉淀和复用。
