# AI 配置诊断与 Docker 同步设计

## 目标

在 AI 配置后台提供可执行、可解释的诊断能力，让管理员能够区分：

- 当前能力没有选择模型；
- 服务商或模型已停用；
- 必填凭据、服务商参数或模型参数不完整；
- 文本模型真实请求失败；
- 多媒体能力配置完整但适配器尚未实现；
- 能力已经通过真实服务检查。

诊断功能必须同时进入源码部署、Linux 部署包和 Docker 镜像，三种部署方式使用同一套 API 与业务逻辑。

## 诊断范围

### 能力配置检查

按后台支持的每个 AI 能力检查当前选择模型。运行时只读取 `isSelected`，`isDefault` 仍然只是推荐参考，不参与诊断结果和模型路由。

基础检查包括：

1. 是否存在启用的当前选择模型；
2. 所属服务商是否启用；
3. 模型名称、Base URL 和通用 API Key 是否满足该服务类型要求；
4. 服务商 settings、模型 settings 和加密凭据元数据是否能够安全解析；
5. 阿里多媒体能力的专属参数是否完整。

阿里能力要求：

- `SPEECH_TO_TEXT`：主 API Key 或 ASR API Key、语言、采样率、编码；
- `TEXT_TO_SPEECH`：主 API Key、音色、采样率、格式；
- `DIGITAL_HUMAN_REALTIME`：主 API Key、RTC App ID、RTC App Key、Avatar ID、RTC 模式；
- `VISION_BEHAVIOR_ANALYSIS`：主 API Key、最低置信度、抽帧间隔、最多帧数。

诊断响应和日志不得返回密钥明文、加密载荷、完整上游错误正文或候选人数据。

### 混合连通性检查

文本能力使用真实最小请求检查：

- `INTERVIEW_DIALOGUE`
- `INTERVIEW_OUTLINE`
- `INTERVIEW_FOLLOW_UP`
- `REPORT_ANALYSIS`
- `COMPANY_RESEARCH`
- `SAFETY_REVIEW`

请求使用当前选择模型、极低 token 上限和固定诊断提示，不生成面试内容，不写入训练会话，也不记录为成功面试调用。HTTP、超时、认证和模型不存在错误转为安全诊断代码。

多媒体能力在对应真实适配器完成前只执行配置检查。配置完整时返回 `CONFIGURED_NOT_ADAPTED`，不能标记为“真实服务可用”。适配器完成后，诊断服务通过统一的 `checkConnection()` 自动升级为真实检查，无需修改后台页面协议。

## API

新增受管理员认证保护的接口：

- `GET /api/ai-services/diagnostics`：返回全部能力的当前状态摘要；
- `POST /api/ai-services/diagnostics`：诊断一个能力，输入 `{ capability, liveCheck }`。

状态枚举：

- `AVAILABLE`：真实检查通过；
- `CONFIG_VALID`：配置检查通过，但调用方未要求真实检查；
- `CONFIGURED_NOT_ADAPTED`：多媒体配置完整，适配器尚未落地；
- `NOT_SELECTED`：没有当前选择模型；
- `MISCONFIGURED`：凭据或参数缺失；
- `UNREACHABLE`：真实请求失败或超时。

响应包括能力、服务商显示名、模型显示名、模型名称、检查模式、状态、耗时、安全提示和检查时间。响应不包含数据库内部加密字段。

## 后台界面

在 AI 配置页增加“配置诊断”区域：

- 按能力显示当前使用模型和状态；
- 提供“检查配置”和“真实连通测试”命令；
- 文本能力允许真实连通测试；
- 尚未适配的多媒体能力将真实测试按钮解释为配置检查，并明确显示“已配置，等待适配器”；
- 单项检查期间只锁定该能力按钮；
- 网络错误和 API 错误统一显示中文安全提示。

界面不自动执行付费真实请求。首次加载只读取摘要，真实检查必须由管理员主动触发。

## Docker 与 Linux 同步

Docker 镜像继续从同一工作区构建，不维护第二份应用代码。为防止容器版本遗漏功能：

1. Docker 构建必须包含诊断 API 和后台静态资源；
2. Docker Compose 继续使用 `/api/health` 做容器就绪检查；
3. 增加 Docker 部署契约测试，验证诊断路由未被 `.dockerignore` 排除；
4. Linux 部署文档增加更新命令和诊断验证命令；
5. 每次发布使用 `docker compose up -d --build` 重建镜像，数据库继续挂载 `app-data`；
6. 诊断接口受现有管理员认证保护，不能作为公开健康检查端点。

## 错误处理与日志

诊断错误使用稳定代码，前端不解析厂商错误正文。服务端可以记录经过截断和脱敏的失败原因，但不得记录凭据、请求 Authorization 头或加密字段。

诊断不写 `AiCallLog` 的面试成功记录。后续加入审计日志时，记录管理员触发诊断的能力、时间、结果代码和耗时。

## 测试

测试覆盖：

- 当前选择与推荐参考的隔离；
- 未选择、服务商停用、配置缺失和配置完整状态；
- 阿里 ASR、TTS、Avatar、行为分析参数规则；
- 文本真实检查成功、超时、401、404、429 和 5xx；
- 响应与错误不泄露密钥和加密数据；
- 后台状态与按钮渲染；
- Docker、Linux 部署文档和健康检查契约；
- TypeScript、完整单元测试和 Next.js 生产构建。

真实厂商联调需要管理员在本地或服务器后台保存有效凭据后主动执行，不在自动测试中调用付费外部服务。
