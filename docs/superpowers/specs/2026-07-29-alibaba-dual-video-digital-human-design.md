# 阿里云双视频数字人接入设计

日期：2026-07-29

## 1. 背景与目标

项目当前已经具备面试题生成、动态追问、训练记录、报告、Qwen/CosyVoice 语音合成、灵眸实时会话适配器、本地数字人降级和多服务商配置能力。此前接入的硅基 DUIX 订阅与使用流程不再符合当前调试需求，本阶段将 DUIX 从新配置和运行链路中移除。

新的数字人视频链路使用两个阿里云异步视频服务：

1. 阿里云灵眸播报视频合成，作为预设题的首选服务。
2. 阿里云百炼悦动人像 EMO，作为预设题的备用服务，并与灵眸共同参与动态追问竞速。
3. 两个服务均不能在规定时间内提供视频时，使用本地动态头像和 Qwen 情绪语音继续面试。

本阶段以真实服务适配、可诊断性和本机调试为主要目标。没有真实凭据或 OSS 配置时，系统必须明确显示未配置，不能用假响应宣称服务可用。

## 2. 已确认决策

- 不接入酷虎云。
- 不接入数字人直播。
- 不再把 DUIX 作为可新增、默认或运行时数字人服务。
- 灵眸播报视频合成优先于 EMO 用于预设题。
- 动态追问同时提交灵眸和 EMO，应用最先观察到的成功结果。
- 动态追问的云视频等待上限为 8 秒。
- 灵眸任务在第 3 秒和第 6 秒查询。
- EMO 任务在第 8 秒执行一次最终查询。
- 8 秒内没有可播放视频时立即降级，不能继续阻塞面试。
- 调试界面支持“自动链路”“仅灵眸”“仅 EMO”三种模式，默认使用自动链路。
- 灵眸和 EMO 可以共享同一面试官形象，也可以配置为两位不同面试官。
- 当配置为两位面试官时，动态追问由最先生成成功视频的面试官提问。
- 另一服务稍后完成的结果不会抢占正在播放的视频，可以进入缓存供回放或复用。
- 运行时不使用 Mock；自动化测试不能被描述为真实服务可达性证明。
- 每个实施阶段完成后执行测试、提交并推送 GitHub。
- 如果使用 Docker 验证，结束后必须停止容器并关闭 Docker Desktop。

## 3. 方案比较

### 3.1 采用：预生成加有界竞速

预设题在训练任务创建、题纲完成或进入房间预热时提前生成。动态追问在文本与情绪语音就绪后并行提交两种云视频任务，并执行 8 秒有界竞速。

优点：

- 预设题大部分时间可以无等待播放。
- 动态追问有明确的等待上限。
- 两个真实服务可以分别诊断和对比。
- 保留现有面试题、追问、记录和报告事实来源。

代价：

- 动态追问可能产生两份视频生成费用。
- EMO 官方建议使用更长的状态查询间隔，因此在 8 秒窗口内只执行一次最终查询，竞速会略微偏向灵眸。
- 需要持久化任务状态和清理临时媒体。

### 3.2 未采用：每题顺序生成

每次先完整等待灵眸，失败后再等待 EMO。实现较简单，但供应商超时会叠加，容易造成明显冷场。

### 3.3 未采用：无期限并行等待

两个任务并行生成并等待首个结果，不设置硬超时。成功率较高，但无法控制面试停顿，不符合实时面试体验要求。

## 4. 总体架构

新增统一的异步数字人视频渲染边界。面试业务只提交“问题文本、情绪音频、面试官配置和调试模式”，不直接依赖任何供应商字段。

渲染边界包含：

- 灵眸播报视频适配器：查询模板、按模板变量创建视频、查询视频状态。
- EMO 适配器：提交悦动人像异步任务、查询任务状态、解析输出视频。
- OSS 媒体存储适配器：上传头像和 Qwen TTS 音频，生成短期可访问 URL，执行过期清理。
- 渲染编排器：预生成、双任务竞速、8 秒截止、胜出选择、缓存和本地降级。
- 调试诊断器：验证本地配置、执行管理员明确触发的真实连通性测试、记录脱敏结果。

浏览器只与项目自己的会话和渲染接口通信。阿里云 API Key、RAM AccessKey、OSS 签名能力和完整供应商响应不得进入浏览器。

## 5. 服务商与模型配置

### 5.1 百炼 EMO

复用 `TONGYI` 服务商中的百炼 API Key，新增 `DIGITAL_HUMAN_VIDEO` 能力模型：

- 模型名：`emo-v1`
- 输入：人物肖像图片 URL、Qwen TTS 音频 URL
- 输出：异步视频任务与成功后的视频 URL
- 配置：人物画幅、动作模板以及供应商明确支持的输出选项

EMO 只接受可访问的 HTTP/HTTPS 输入，不接受 Windows 本地路径。适配器使用 OSS 短期签名 URL 或百炼明确支持的临时上传能力。

### 5.2 灵眸播报视频

复用 `LINGMOU` 服务商的 RAM 凭据体系，新增 `DIGITAL_HUMAN_VIDEO` 能力模型：

- 模型名：`lingmou-broadcast-video`
- 输入：播报模板 ID、模板变量、Qwen TTS 音频 URL 及所需图片 URL
- 输出：异步播报视频任务与成功后的视频 URL
- 配置：模板 ID、变量映射、分辨率、帧率、水印和导出模式

灵眸实时会话能力与播报视频能力使用不同模型设置和适配器，不能混用 `configId`、`instanceId` 与播报模板 ID。

### 5.3 OSS

OSS 配置包含：

- 地域
- Endpoint
- Bucket
- 临时对象前缀
- 独立的最小权限 RAM 凭据

OSS 凭据与灵眸凭据分别加密保存。实现可以提供显式的“使用已有 RAM 凭据”迁移入口，但不作为默认安全建议。

### 5.4 自定义配置

服务商和模型仍遵循现有下拉框与“自定义”配置规则。阿里预设只填充已知字段，不阻止管理员创建其他兼容模型。

## 6. 面试官配置

新增可复用的面试官资料：

- 显示名称
- 头像或人物肖像素材
- 音色
- 情绪与风格策略
- 灵眸模板和变量映射
- EMO 画幅与动作设置

双服务配置默认开启“同步面试官形象”。开启时，两种服务共享姓名、头像和基础音色；关闭后可分别配置两位面试官。

当两位面试官参与动态竞速时，胜出任务决定本轮提问者。训练轮次需要记录面试官资料 ID、供应商、模型、渲染任务 ID、生成耗时和降级状态，确保回放和报告可以解释人物切换。

## 7. 数据模型

新增或扩展以下持久化实体：

### 7.1 面试官资料

保存公开展示字段、加密媒体引用、同步状态和供应商映射。删除资料前必须检查训练任务和历史轮次引用。

### 7.2 数字人渲染任务

保存：

- 训练任务、训练会话和轮次归属
- 问题文本哈希和音频素材引用
- 调试模式
- 截止时间
- 当前状态
- 胜出尝试
- 本地降级原因
- 创建、完成和过期时间

状态至少包含 `PENDING`、`SUBMITTED`、`RACING`、`READY`、`FALLBACK`、`FAILED` 和 `EXPIRED`。

### 7.3 供应商渲染尝试

每个渲染任务最多包含一个灵眸尝试和一个 EMO 尝试，记录：

- 供应商和模型
- 上游任务 ID
- 安全状态码
- 下次允许查询时间
- 提交、首次查询、完成和失败时间
- 输出媒体引用
- 脱敏错误码

数据库唯一约束阻止相同渲染任务重复提交同一供应商。幂等键使用内部任务 ID，不包含问题原文或凭据。

### 7.4 媒体资产

保存 OSS 对象键、内容类型、大小、用途、过期时间和清理状态。数据库不保存公开长期 URL；需要访问时生成短期签名 URL。

## 8. 运行流程

### 8.1 预设题

1. 面试题纲确定后生成题目所需的 Qwen 情绪语音。
2. 上传头像和音频到 OSS。
3. 首先提交灵眸播报视频任务。
4. 灵眸明确失败、限流或不可用时提交 EMO。
5. 成功结果写入缓存，并与题目文本哈希和面试官资料版本绑定。
6. 候选人进入房间后优先播放缓存视频。
7. 缓存尚未完成时使用与动态追问相同的 8 秒有界等待和本地降级。

题目文本、音色、情绪策略、头像或模板变化时缓存键必须变化，不能播放旧版本视频。

### 8.2 动态追问

1. 现有面试引擎生成追问文本和情绪策略。
2. 生成对应的 Qwen TTS 音频；双面试官模式可按资料配置生成各自音频。
3. 上传所需媒体并同时提交灵眸和 EMO。
4. 灵眸在第 3 秒和第 6 秒查询。
5. EMO 在第 8 秒执行一次查询。
6. 应用最先观察到的成功结果；若同一次检查中两者均成功，优先使用完成时间更早的结果，缺少可靠完成时间时使用灵眸。
7. 第 8 秒仍没有成功结果时，立即播放本地动态头像和 Qwen 情绪语音。
8. 未胜出的任务继续进入后台收尾；成功视频可以缓存，但不能中途替换正在播放的提问者。

“最先完成”在产品语义上指应用最先观察到 `SUCCESS`，不承诺等同于供应商内部的真实完成时刻。

### 8.3 调试模式

- `AUTO_RACE`：预设题灵眸优先，动态追问双服务竞速。
- `LINGMOU_ONLY`：只提交灵眸，超时或失败后本地降级。
- `EMO_ONLY`：只提交 EMO，超时或失败后本地降级。

调试模式只影响新任务，不能改变已经提交任务的供应商集合。

## 9. 前端体验

面试房间保持问题文字始终可见，并增加：

- 面试官姓名和当前供应商标识
- 分析、生成、播放和本地降级状态
- 最长 8 秒的非精确进度提示
- 生成期间的空闲动作和“正在分析回答”提示
- 视频切换前的短淡入，避免画面突变

候选人界面不显示上游任务 ID、原始错误和费用信息。管理员调试页显示：

- 每个供应商的提交和查询时间
- 当前安全状态
- 生成耗时
- 胜出服务
- 降级原因
- 预计产生付费调用的操作确认

## 10. 错误处理

- 未配置：不提交云任务，返回明确的 `NOT_CONFIGURED` 状态。
- 凭据错误：使用固定鉴权错误码，不返回供应商原文。
- OSS 上传失败：不提交依赖该素材的云任务。
- 灵眸明确失败：预设题转 EMO；动态追问继续等待已提交的 EMO。
- EMO 明确失败：继续等待灵眸。
- 查询限流：遵守下一次允许查询时间，不进行紧密重试。
- 8 秒截止：原子地选出胜者或写入本地降级，迟到结果不能覆盖决定。
- 浏览器离开：云任务继续收尾，内部会话所有权和清理逻辑继续有效。
- 应用重启：从数据库恢复尚未完成的任务，不依赖进程内 Promise 作为事实来源。

## 11. 安全与隐私

- API Key、AccessKey 和 OSS 凭据使用现有 AES-256-GCM 配置加密机制保存。
- 建议创建独立的最小权限 OSS RAM 用户。
- 短期签名 URL 只在需要调用供应商或播放结果时生成。
- OSS 对象名使用随机标识，不包含候选人姓名、手机号、岗位或问题文本。
- 默认最长保留 24 小时，任务结束后进入清理队列。
- 日志不得包含密钥、签名 URL、原始音频、完整供应商响应或候选人隐私内容。
- 管理员真实诊断需要二次确认，并明确提示可能产生费用。
- 浏览器端不能获得阿里云长期凭据。

## 12. DUIX 退出策略

- 从 `aiProviderTypes`、新建服务商选项、模型推荐和默认选择中移除 DUIX。
- 数据迁移禁用现有 DUIX 服务商与模型，并取消其当前选中状态。
- 删除 DUIX H5 SDK 浏览器适配器、服务端签名适配器和 npm 依赖。
- 数字人房间不再创建新的 `DUIX_H5` 会话。
- 历史数据库会话和日志保留原始字符串，保证审计和旧数据可读。
- 清理前确认没有运行中的 DUIX 会话；迁移不得删除历史训练记录。

## 13. 测试策略

自动化测试覆盖：

- 服务商、模型、OSS 和面试官配置验证。
- 凭据加密、解密失败和响应脱敏。
- 灵眸与 EMO 真实协议请求构造和响应解析。
- OSS 对象命名、签名有效期和清理调度。
- 预设题灵眸优先与 EMO 备用。
- 动态追问双提交、第 3/6/8 秒查询、胜者原子选择和迟到结果处理。
- 三种调试模式。
- 相同面试官和双面试官资料。
- 8 秒本地降级和面试不中断。
- 应用重启后的任务恢复。
- DUIX 禁用迁移与 Docker 源码依赖同步。

测试可以通过依赖注入验证纯逻辑和协议契约，但不能将注入结果、测试夹具或存根描述为真实服务成功。真实可达性只有在管理员配置凭据并明确触发付费诊断或真实短任务后才能确认。

每个实施阶段至少运行相关测试、全量 Vitest、生产构建和 `git diff --check`。涉及 Dockerfile、依赖或部署包的阶段还要构建同源 Docker 镜像并执行健康检查，完成后运行：

```powershell
docker compose down --remove-orphans
docker desktop stop
```

## 14. 实施阶段

### 阶段 1：配置、数据模型与 DUIX 退出

新增 OSS、异步视频模型、面试官资料和渲染任务数据结构；更新后台配置；禁用 DUIX 并移除其运行依赖。完成后测试、提交并推送。

### 阶段 2：OSS、灵眸和 EMO 适配器

实现真实请求构造、响应解析、异步状态、媒体上传和脱敏诊断。没有凭据时只验证配置和协议契约，不宣称云服务可达。完成后测试、提交并推送。

### 阶段 3：预生成与动态竞速

实现预设题缓存、双服务竞速、8 秒截止、胜出选择、迟到任务收尾和本地降级。完成后测试、提交并推送。

### 阶段 4：面试房间与调试界面

实现面试官同步/拆分配置、三种调试模式、生成状态、胜出信息和安全诊断。完成后测试、构建、提交并推送。

### 阶段 5：Docker、Linux 与真实联调准备

同步 Docker 和源码依赖，更新 Linux 部署文档、RAM/OSS 最小权限配置说明和真实联调清单。执行同源镜像验证后停止 Docker。完成后提交并推送。

### 阶段 6：用户配置后的真实联调

用户在本机后台录入 OSS、灵眸和百炼凭据后，依次验证：

1. OSS 上传和清理。
2. 仅灵眸短任务。
3. 仅 EMO 短任务。
4. 自动动态竞速。
5. 8 秒降级。
6. 面试结束后的任务与媒体清理。

真实联调会产生费用，必须由管理员明确触发。

## 15. 验收标准

- 后台不再提供 DUIX 新配置，运行时不再加载 DUIX SDK。
- 可以配置灵眸播报、EMO、OSS 和一位或两位面试官。
- 预设题优先使用已生成缓存。
- 动态追问同时提交两个云任务，并在 8 秒内选出已观察到的首个成功结果。
- 8 秒内没有云视频时，面试通过本地头像和 Qwen 情绪语音继续。
- 页面能说明本轮面试官、供应商、耗时和降级状态。
- 云凭据和签名 URL 不出现在浏览器持久化、日志或普通错误响应中。
- 无凭据时显示未配置，不返回假成功。
- 源码构建、自动化测试和 Docker 同源验证通过。
- 使用 Docker 的验证结束后容器和 Docker Desktop 均已停止。
